Narrative

Artifact Description

The artifact for this milestone is the Pirate Intelligent Agent, originally developed for CS 370. The project trains a deep Q-learning agent to navigate a maze environment toward a target cell. The instructor-provided TreasureMaze class represents the maze and the agent's position within it, and the instructor-provided GameExperience class stores past training episodes and samples them into batches during training. I wrote the model architecture, the custom TensorFlow training step, and the qtrain() function that runs the full epsilon-greedy training loop, calling the training step each episode and tracking the agent's win rate to detect when it has learned to solve the maze consistently.

Justification and Description of Enhancement

My original enhancement plan from Module One was to add an experience replay buffer, based on an assumption that the project trained on each move as it happened without storing any history of past moves to learn from. Returning to the real project code for this milestone, I found that assumption was incorrect: the instructor-provided GameExperience class already implements a replay buffer, sampling past episodes uniformly at random into a training batch each epoch. Rather than build a feature that already existed, I corrected the plan and implemented Prioritized Experience Replay, a published deep reinforcement learning technique that replaces uniform random sampling with sampling weighted toward the episodes the network is currently predicting worst, measured by temporal-difference error. The reasoning behind it is straightforward: an episode the network already predicts correctly teaches it very little the next time it is replayed, while an episode it is getting wrong is the one most useful to revisit, so weighting the sample toward those episodes should let the network learn the maze in fewer training epochs.

I implemented this as a new PrioritizedReplayBuffer class. It stores each episode together with a priority value, raises each priority to a tunable exponent to control how strongly sampling favors high-priority episodes versus staying close to uniform, draws a training batch using those weighted probabilities, and exposes an update_priorities() method that the training loop calls after each batch to refresh priorities using the temporal-difference error the network just produced for those episodes. I did not implement the full importance-sampling weight correction that is part of the published version of this technique, which compensates for the statistical bias that prioritized sampling introduces. I limited the scope to the prioritized sampling mechanism itself so the enhancement would be one clearly demonstrable, fully understood change rather than a partial reimplementation of the entire published algorithm, and I am disclosing that simplification here rather than presenting the implementation as more complete than it is.

A separate disclosure concerns how this enhancement was tested. The original project ran inside SNHU's Codio environment, which I no longer have access to. To verify that the enhanced training loop actually runs and trains correctly, I rebuilt local versions of TreasureMaze.py and GameExperience.py based on the method signatures, documented behavior, and exact reward values visible in my own already-submitted, graded notebook output from the original course. These reconstructed files are not the instructor's original files and are not part of the enhancement itself. I included them in a separate folder labeled as not graded so that the benchmark can be reproduced, and they exist only as a local test harness so that I could run a real, honest comparison between the original and enhanced training loops on my own machine rather than submitting an enhancement I had not actually run. The code being submitted as the enhancement itself is the new PrioritizedReplayBuffer class and the new qtrain_per() function; the model architecture, the training step, and the original qtrain() function are unchanged from my original, graded submission.

To confirm the enhancement provides a real improvement rather than just added complexity, I ran the original qtrain() and the new qtrain_per() under identical conditions, the same maze, the same model architecture, the same hyperparameters, and the same epoch ceiling, and recorded the epoch at which each reached a sustained 100% win rate. The original qtrain() reached that benchmark at epoch 484. The enhanced qtrain_per() reached the same benchmark at epoch 280, a reduction of roughly 42% in the number of epochs needed to converge. That result is consistent with what prioritized replay is intended to produce: by replaying the episodes the network is still getting wrong more often than the episodes it has already mastered, the agent reaches a correct policy in fewer training epochs.

Course Outcomes

This enhancement meets the outcomes I identified for this artifact in Module One. Outcome 3 asked me to design and evaluate a computing solution using algorithmic principles while managing the trade-offs involved in design choices; choosing to prioritize sampling by temporal-difference error instead of GameExperience's uniform sampling, and the decision to implement prioritization without the full importance-sampling correction, are exactly that kind of trade-off, favoring a focused, honestly scoped change verified by a direct empirical benchmark over a complete, unverified reimplementation of the entire published algorithm. Outcome 4 asked me to use well-founded and innovative techniques and tools to implement a computing solution that delivers value and accomplishes a specific goal; Prioritized Experience Replay is an established technique in deep reinforcement learning, and the measured reduction from 484 to 280 epochs is direct evidence that applying it here delivered real value rather than only additional code.

I do have a change to report to the original enhancement plan. The plan from Module One, adding a replay buffer because the original implementation appeared to lack one, was based on an assumption about the codebase that I did not verify until returning to the real project files for this milestone, and that assumption turned out to be incorrect. I am reporting that correction here rather than letting the earlier, inaccurate plan stand, and replaced it with Prioritized Experience Replay, an enhancement that targets a real limitation of the existing buffer's uniform sampling rather than a limitation that did not actually exist.

Reflection

The most useful thing I learned in this milestone was to verify my own assumptions about a codebase before planning an enhancement around them. The replay-buffer plan from Module One sounded reasonable on its own, but it was built on a guess about what the original project contained rather than a fresh reading of the actual code, and the guess turned out to be wrong. Catching that before building anything, rather than after, was only possible because I went back to the real source material directly instead of relying on my memory of a project completed in an earlier term.

The most concrete challenge in this milestone was practical rather than conceptual: verifying that the enhanced training loop actually worked without access to the original Codio environment. I resolved this by rebuilding local versions of TreasureMaze.py and GameExperience.py from the evidence available in my own already-graded notebook output, which let me run the original and enhanced training loops under identical conditions and compare the epoch at which each reached a sustained 100% win rate, rather than relying on a single run or a quick visual check to decide whether the enhancement actually helped.

4class PrioritizedReplayBuffer:
5 """
6 Custom data structure for the CS 499 algorithms/data structures
7 enhancement. Stores past game episodes together with a priority value
8 and samples training batches with probability proportional to each
9 episode's priority (derived from its TD-error), instead of sampling
10 uniformly at random the way the original GameExperience class does.
11 This means the agent spends more training time on the experiences it
12 is currently predicting worst, rather than treating every past episode
13 as equally useful to learn from.
14 """
